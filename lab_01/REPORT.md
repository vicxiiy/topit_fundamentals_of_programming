### Задание 1. От исходного кода к байткоду
#### Часть 1. Режимы запуска
`print(2 + 3 * 4)`

Результат в REPL отображается автоматически: 14 При запуске файла: ничего не выводится. После добавления `print()`: в терминале появляется 14.
#### Объяснение: 
В интерактивном режиме (REPL) интерпретатор Python автоматически выводит результат каждого выражения. При запуске файла как программы этот механизм отключен. Результат в терминале появляется только при вызове функции `print()`.

#### Часть 3. AST и байткод
В AST нашлось:
##### 1.	Присваивание: 
```
Assign(
   targets=[
      Name(id='course', ctx=Store())],
   value=Constant(value='Python'))
```
##### 2.	Арифметическая операция:  
```
Assign(
   targets=[
      Name(id='hours', ctx=Store())],
   value=BinOp(
      left=Constant(value=4),
      op=Mult(),
      right=Constant(value=2)))
```
##### 3.	Вызов print():
```
Expr(
   value=Call(
      func=Name(id='print', ctx=Load()),
      args=[
         JoinedStr(…)])
```
#### Фрагмент байткода:
```
             …
5           LOAD_CONST               1 ('Python')
            STORE_NAME               1 (course)

6           LOAD_SMALL_INT           8
            STORE_NAME               2 (hours)

7           LOAD_NAME                0 (print)
            PUSH_NULL
            LOAD_NAME                1 (course)
            FORMAT_SIMPLE
            LOAD_CONST               2 (': ')

```
В байткоде за загрузку константы отвечает LOAD_CONST, а за вызов функции - CALL.

#### Контрольный вопрос: Почему байткод CPython нельзя считать машинным кодом процессора?

Байткод - это не то, что процессор способен выполнить напрямую. Его понимает и обрабатывает интерпретатор Python: он построчно читает байткод и уже сам даёт процессору команды, что делать. Машинный код, в отличие от байткода, жёстко привязан к архитектуре конкретного процессора - для разных процессоров он разный.

### Задание 2. Имена, объекты и сравнение

Прогноз:
```
a == b: True
a is b: True
a == c: True

```
Фактический результат совпал с прогнозом: `a` и `b` – это два имя, указывающие на один и тот же объект в памяти. Имя `c` – ссылка на другой объект, другой id, у которого просто совпадает значение.

__1.__	 
```
a ─┐
   ├──> [объект `int`, значение=1000, id один]
b ─┘
c ────> [объект `int`, значение=1000, id второй]
```

__2.__	Равенство значений – сравнивает содержимое объектов, отвечает на вопрос «одинаковы ли значения?». Идентичность объектов – сравнивает адреса объектов в памяти, отвечает на вопрос «это один и тот же объект или два разных объекта с одинаковым содержимым?»

__3.__	Так как оператор == вызывает метод `__eq__`, который можно переопределить в пользовательском классе (и он может вернуть True даже для объекта, не являющегося None), то корректной проверкой на None будет являться is, потому что она сравнивает идентичность объектов напрямую и не зависит от того, как в классе реализован `__eq__`. :
`c = None`
`print("c is None:", c is None)`

__4.__	Оба сравнения дают True. Строку `"python"`, написанную прямо в коде, Python хранит в одном экземпляре и переиспользует её при повторе.
Вторая строка склеена из кусочков прямо в коде `("py" + "thon")`, и Python считает результат заранее, до запуска программы. Получается та же строка `"python"`, поэтому он снова использует уже готовый объект вместо нового.

__5.__	`==` используется для сравнения значений, когда нужно узнать, одинаковы ли данные - числа, строки, списки и т.д. `is` используется только для сравнения идентичности объектов - это один и тот же объект в памяти или два разных объекта с одинаковым значением.

#### Контрольные вопросы:

__1.__	Инструкция `b = a` не создаёт копию объекта - она создаёт новую ссылку `b`, которая указывает на тот же объект, что и a. Это подтверждается совпадением `id(a)` и `id(b)`.

__2.__	`type()` возвращает класс объекта, показывает, к какому виду данных он относится. `id()` возвращает уникальный идентификатор объекта, который в CPython фактически соответствует адресу объекта в памяти на время его существования.

__3.__	`None` - единственный объект своего типа, существующий в программе в одном экземпляре, поэтому сравнивать его по идентичности через `is` корректно, быстрее и надёжно. Числа и строки, наоборот, могут существовать как разные объекты с одинаковым значением, поэтому для них важно именно значение, а не факт, что это буквально один и тот же объект в памяти.

### Задание 3. Числовые типы, операции и преобразования

#### Эксперимент А:
`/` - оператор вещественного деления: он всегда возвращает `float`, даже если числа делятся нацело, потому что должен сохранить дробную часть результата. `//` - оператор целочисленного (`floor`) деления: он округляет результат вниз до целого. Если оба числа типа `int`, то и результат `//` будет `int` (`17 // 5 == 3`); если хотя бы одно число типа `float`, результат `//` тоже станет `float` (`17.0 // 5 == 3.0`). 

#### Эксперимент B:
Во многих языках целые числа хранятся в ячейке фиксированного размера (32 или 64 бита), поэтому у них есть жёсткий верхний предел, и при его превышении происходит переполнение. Тип `int` в Python имеет неограниченную точность - внутри CPython хранит число как массив цифр по 30 бит, который автоматически расширяется по мере роста значения. Единственное ограничение - объём доступной оперативной памяти, поэтому `2 ** 1000` вычисляется абсолютно точно, без переполнения.

#### Эксперимент C:
При исследовании выражения `result = 0.1 + 0.2` получились ответы:
```
result = 0.30000000000000004
result == 0.3: False
result - 0.3 = 5.551115123125783e-17
math.isclose(result, 0.3): True
```
Компьютер хранит дробные числа в двоичном виде, а не в десятичном. Многие простые на вид десятичные дроби, например 0.1 и 0.2, в двоичном виде превращаются в бесконечную дробь, которую приходится обрезать - отсюда и берётся крошечная погрешность. Поэтому 0.1 + 0.2 получается чуть больше, чем настоящие 0.3, и `result == 0.3` даёт `False`.

__Правило безопасного сравнения:__ дробные числа нельзя сравнивать через `==`. Нужно проверять, что они достаточно близки друг к другу - например, через `math.isclose(a, b)`.

#### Контрольные вопросы:

__1.__	Оператор `/` в Python 3 - это оператор вещественного деления, а не целочисленного. Он спроектирован так, чтобы всегда возвращать математически точный результат, включая дробную часть, даже если она равна нулю.

__2.__	`int("42")` - Python разбирает текст "42" как запись целого числа и создаёт из неё `int`. `int(42.9)` - это усечение числа с плавающей точкой: дробная часть отбрасывается, то есть `int(42.9)` = 42.

__3.__	Из проверенных в эксперименте D falsy являются: `bool(0)` и `bool("")`.

### Задание 5. Информационная карточка вычислительного эксперимента
```
"""
Информационная карточка вычислительного эксперимента.

Программа запрашивает у пользователя сведения об исследователе и об
эксперименте (имя исследователя, название эксперимента, число запусков,
длительность одного запуска, а также вещественную и мнимую части
комплексного коэффициента), выполняет ряд простых вычислений без
использования условных операторов и циклов, и выводит аккуратно
оформленную карточку с результатами, а также диагностическую строку
с типами всех введённых значений.
"""

# Ввод данных
researcher_name = input("Введите имя исследователя: ")
experiment_name = input("Введите название эксперимента: ")
runs_count = int(input("Введите количество выполненных запусков: "))
run_duration = float(input("Введите длительность одного запуска в секундах: "))
coeff_real = float(input("Введите действительную часть коэффициента: "))
coeff_imag = float(input("Введите мнимую часть коэффициента: "))

# Вычисления
total_duration_seconds = runs_count * run_duration
total_duration_minutes = total_duration_seconds / 60
coefficient = complex(coeff_real, coeff_imag)
magnitude_squared = coeff_real ** 2 + coeff_imag ** 2
has_runs = bool(runs_count)

# Вывод карточки
separator = "=" * 40

print(separator)
print(f"ЭКСПЕРИМЕНТ: {experiment_name}")
print(f"Исследователь: {researcher_name}")
print(f"Запуски: {runs_count}")
print(f"Общее время: {total_duration_seconds:.2f} с ({total_duration_minutes:.2f} мин)")
print(f"Коэффициент: {coefficient}")
print(f"Квадрат модуля: {magnitude_squared:.2f}")
print(f"Есть выполненные запуски: {has_runs}")
print(separator)

# Диагностическая строка с типами введённых значений
print(
    "Типы введённых значений: "
    f"researcher_name={type(researcher_name).__name__}, "
    f"experiment_name={type(experiment_name).__name__}, "
    f"runs_count={type(runs_count).__name__}, "
    f"run_duration={type(run_duration).__name__}, "
    f"coeff_real={type(coeff_real).__name__}, "
    f"coeff_imag={type(coeff_imag).__name__}"
)
```

__1.__	researcher_name - `str` 

experiment_name - `str` 
runs_count - `int` 
run_duration - `float` 
coeff_real - `float` 
coeff_imag - `float` 
total_duration_seconds - `float` 
total_duration_minutes - `float` 
coefficient - `complex` 
magnitude_squared - `float` 
has_runs - `bool` 
separator - `str`

__2.	Для строки:__
`magnitude_squared = coeff_real ** 2 + coeff_imag ** 2`
__Литералы:__ 2 и 2 - целочисленные литералы.
__Имена:__ magnitude_squared, coeff_real, coeff_imag.
__Операторы:__ ** (возведение в степень), + (сложение), = (присваивание) 
__Вызовы функций:__ оба возведения в степень и сложение реализуются через вызовы специальных методов объектов: `coeff_real.__pow__(2)`, `coeff_imag.__pow__(2)`, а затем `.__add__()` для сложения результатов. 

__4.	Путь программы от исходного файла до выполнения:__
__Исходный файл__ - текст программы, записанный в виде обычных символов; __Разбор исходного текста__ - интерпретатор читает текст и делит его на токены: имена, числа, операторы, скобки. Затем строит из этих токенов дерево разбора; __AST__ - дерево разбора упрощается: остаётся только смысл инструкций (присваивание, вызов функции, арифметическое действие); __Компиляция в байткод__ - на основе AST создаются низкоуровневые команды для виртуальной машины Python; __Выполнение виртуальной машиной CPython__ - команды выполняются по очереди: создаются объекты, вызываются функции, имена связываются со значениями, и в результате программа выводит ответ.

__5.__	`input()` всегда возвращает объект типа `str`, независимо от того, что ввёл пользователь. Строка и число - это объекты разных типов, и операторы ведут себя с ними по-разному: например, * для строк означает повторение, а не умножение. Без явного преобразования арифметическое выражение с такой строкой либо привело бы к ошибке TypeError, либо дало бы неожиданный результат. Поэтому `int()` и `float()` создают новый объект нужного числового типа, с которым арифметические операторы работают корректно.

#### Контрольный вопрос:

При повторном присваивании нового значения уже существующему имени сам старый объект не меняется, а создаётся новый объект с новым значением, имя отвязывается от старого объекта и привязывается к новому. Если на старый объект больше никто не ссылается, он становится недостижимым, и сборщик мусора со временем освобождает память. То есть меняется не объект, а связь между именем и объектом - имя начинает указывать на другой объект в памяти. Это верно для всех имён в программе: переприсваивание создаёт новую привязку к новому объекту, а не изменяет старый.

В результате выполнения лабораторной работы можно выделить три особенности Python, которые оказались наиболее неожиданными:
__1.__ Эксперимент с `a = 1000`, `b = a`, `c = 1000` показал, что `a == c (True)`, но `a is c (False)`: визуально одинаковый код не гарантирует один и тот же объект в памяти. Имя - это ссылка, и совпадение или несовпадение id зависит от внутренних оптимизаций интерпретатора, а не от логики программы, поэтому `is` нельзя использовать вместо `==` для сравнения значений.
__2.__ `0.1 + 0.2 != 0.3`. Причина заключается в разрыве между десятичным мышлением человека и двоичным хранением чисел с конечной точностью, из-за чего сравнение через `==` заменяется на `math.isclose()`.
__3.__ Нельзя изменить объект, не изменив его id. Строки в Python неизменяемы: методы вроде .upper() не трогают исходный объект, а создают новый с другим id. То есть «изменение» значения переменной на деле означает создание нового объекта и переприсваивание имени, а не модификацию.
